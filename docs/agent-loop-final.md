# 자율 축소 루프 (Autonomous Narrowing Loop) — 최종 설계

> 원칙 1줄: **묻는 게 디폴트가 아니라 예외다.**
> 시스템은 대화 흐름에서 "더 필요한가"를 스스로 판단하고,
> 답할 수 있으면 답하고, 정말 막힐 때만 묻는다.

---

## 0. 전제 — 가진 것, 원하는 것, 찾아주는 것

**가진 데이터 (전부 확정·로컬 보유):**

| 자산 | 내용 | 규모 |
|---|---|---|
| 보고서 카탈로그 | 131건 (보고서명·설명·입력조건·출력컬럼·지표·차원) | `report_catalog_w2d.json` |
| 가문 분류 | 44 family (계약납품요구 38건筆頭) | 주석 스크립트 확정 |
| 파셋 어휘 | dims 23종, channel 4종, item_scope 2종, concepts 8종+ | closed set |
| 검색 인덱스 | BM25 + Jina 1024차원 벡터 131개 | 재빌드 가능 |
| 세션 답지 | 멀티턴 평가셋 (gold/회귀용) | `sessions.jsonl` |

**사용자가 원하는 것:**

> "내가 원하는 **통계 테이블(보고서)** 1개 (또는 몇 개)."

자연어 ("작년 서울 노트북 얼마나 샀어") → 조건(기간·기관·품목·지표) + 차원(별로) 분해가 관건.
사용자는 보고서ID도, 메뉴 위치도 모름. 말로만 설명함.

**시스템이 찾아주는 것 = 식별자 2종 (링크):**

| 식별자 | 형태 | 용도 |
|---|---|---|
| `이동` | 공식 목록 링크 (`data.g2b.go.kr/link/…?reptNm=보고서ID`) | 제목 클릭 → 조회조건 팝업 |
| `직접열기` | 프록시 딥링크 (`?g2bOpen=reptId`) | 팝업 직접 호출 |

즉 본 시스템의 출력 계약은 **"조건이 맞는 보고서의 식별자(링크) + 근거 1줄"** 이다.
숫자 자체를 계산·반환하지 않음 (Level 4 영역, 본 문서 범위 밖).
이 루프의 존재 이유는 **131개 중 1개를 틀리지 않고 가리키는 것** — 그 이상도 이하도 아님.

## 1. 상태 (State)

```text
state = {
  slots:      { family?, dims[], channel?, item_scope?, metric[] },  // 확정된 것
  candidates: [rid...],        // 현재 후보 (stage solver 출력 순서)
  turns:      n,               // clarify 횟수
  asked:      [slot...],       // 이미 물어본 슬롯 (재질문 금지)
  skipped:    [slot...],       // 사용자가 스킵한 슬롯 (영구 제외)
  path:       [...]            // 판단 로그 (관측용)
}
```

- 서버 세션 없음. `query_state` envelope로 클라이언트가 들고 다님 (현행 유지).
- 새 턴마다: 사용자 발화 → 슬롯 병합(교체/추가/`__skip__`) → 아래 루프.

## 2. 턴 판단 (핵심 — 자율성의 전부)

매 턴, 아래 순서대로 **처음 해당되는 것만** 실행. 위에서 걸리면 아래는 안 봄.

```text
1. 즉시 답변: 1위가 2위보다 TIE_GAP 이상 앞섬 → TopN 답변. (묻지 않음)
2. 종료 (포기): turns >= 2 → best-effort 답변. (더 묻지 않음)
3. 종료 (포기): 물을 만한 슬롯이 없음 (asked+skipped 제외 후 후보를 가르는 슬롯 0개)
   → best-effort 답변. (더 물을 게 없음)
4. 되묻기: gain(물으면 좁혀지는 후보 수) > turns*2+1 → 해당 슬롯 1개만 질문.
   - gain 계산: 후보를 슬롯값으로 그룹핑했을 때 남는 최대 그룹 크기 비교.
     예: 후보 8개 → dims 물으면 최대 2개 그룹으로 → gain 6. turns=0이면 기준 1 → 질문.
     후보 8개 → channel 물으면 그대로 8개 → gain 0 → 묻지 않음.
   - 질문 1개에만. 두 개 이상 절대 금지.
5. 그 외: best-effort 답변 (가정 명시).
```

**해석**: 1이 대부분의 케이스를 처리 (묻지 않음). 4는 "물어볼 가치가 수학적으로 있을 때만".
사용자가 느끼기엔 "알아서 답해주고, 진짜 애매할 때만 한 번 물어봄"이 됨.

## 3. 되묻기 세금 (Clarify Tax)

- clarify 1회 = 사용자 1턴 소모로 회계. gain이 세금(`turns*2+1`)을 못 넘기면 묻지 않음.
- 같은 슬롯 재질문 금지 (`asked` 체크). 스킵된 슬롯 영구 제외 (`skipped` 체크).
- 칩은 항상 `그냥 보여줘` 포함 (탈출구). skip → 즉시 best-effort, 추가 질문 없음.

## 4. 하드 가드레일 (LLM 판단과 무관하게 코드로 강제)

- channel/item_scope 명시 불일치 → 탈락 (복구 불가 오답 방지).
- 후보 집합 밖 rid 생성 불가 (답변은 stage 출력에서만. 없는 보고서 링크 생성 원천 차단).
- 쿼리 재작성 시 원문 토큰 삭제 금지 (추가·교체만. "서울 빼고 딴 지역" 사태 방지).
- 턴 cap 2, 전체 타임아웃, quota 초과 시 즉시 best-effort 폴백.
- LLM 호출 실패·파싱 실패 → 그 턴은 best-effort로 (루프 중단 아님, 조용히 격하).

## 5. LLM의 일 (작게 — 판단만)

- 입력: 현재 state 요약 + 후보 5개 요약 (이름·지표·조건 1줄씩).
- 출력 (JSON 강제): `{"action": "answer"|"ask"|"research",
  "slot"?: "dims"|"channel"|..., "reason": "판단 사유 1줄"}`
- 위 §2의 1~5번을 코드로 먼저 판정하고, **회색지대만 LLM에 물음**
  (코드 판정 가능하면 LLM 호출 자체를 안 함 — 대부분 턴이 여기 걸림).
- temperature 0, 출력 스키마 검증, 실패 시 코드 판정으로 폴백.
- 모델: 경량 (판단용이라 reasoning high 불필요). qwen 유지하되 effort low 검토.

## 6. 이상함 대책 (weirdness budget)

- 지표 신설: `weird_rate` — 사람 평가 "이 턴 이상함" 비율. 정확도 지표와 별도 트랙.
- 대표 이상 케이스 + 대응 (코드/프롬프트에 명시):
  - 불필요 clarify → §2 순서 + 세금으로 차단.
  - 쿼리 변질 → 토큰 삭제 금지 가드.
  - 확신 오답 → 후보 집합 제한 + 근거 강제 (현행 유지).
  - 턴마다 딴소리 → temperature 0 + state 기반 (히스토리 재해석 금지, 슬롯 병합만).
- weird_rate 상승 시 루프 진입 조건을 조임 (역방향 안전밸브).
  진입율 자체도 지표 (`loop_rate`) — 30%+면 파서/개념 문제라는 신호.

## 7. 측정

- 기존: recall@5, family 혼동, top1, clarify율 + `loop_rate`, `avg_turns`, `폴백율`, `weird_rate`.
- 세션 답지(`sessions.jsonl`)로 전후 비교. 나빠지면 롤백 1커밋 (루프 on/off 플래그).
- sunk cost 금지: clarify가 도움 안 되면(clarify_gain ≤ 0) clarify 기능 통째로 꺼도 되는 구조 유지.

## 8. 이행 (기존 것 위)

1. §2 턴 판정을 `decideClarify` 자리에 이식 (stage solver·envelope·칩 UI 그대로).
2. §4 가드레일 중 없는 것만 추가 (토큰 삭제 금지 등).
3. LLM 판단은 회색지대 전용으로 작게 시작 (대부분 턴은 코드 판정).
4. e2e + 세션 답지 측정 → weird_rate 표본 평가 → 판정.

## 9. 한 줄 요약

> **답할 수 있으면 답하고, 수학적으로 물을 가치 있을 때만 묻고, 나머지는 포기하고 보여준다.**
> 자율성이란 "똑똑하게 구는 것"이 아니라 "묻지 않아도 될 때 가만히 있는 것"이다.
