# 자율 축소 루프 (Autonomous Narrowing Loop) — 단순화 초안 (D안 스펙)

> 원칙: **답할 수 있으면 답한다. 정말 도움이 될 때만 한 번 묻는다.**
> 상태: UI 라디오 D로 선택 가능. 백엔드 미연결 (D 요청 시 B 동작으로 폴백).
> 상세 설계는 `docs/agent-loop-final.md`, 본 문서는 구현용 단순화 버전.

이 시스템의 목적은 사용자의 자연어 요청을 받아 131개 보고서 중 맞는 보고서를 찾는 것이다.
사용자는 보고서 ID나 메뉴 구조를 알 필요가 없다.
시스템은 사용자가 말한 조건을 해석하고 후보를 줄인 뒤, 충분히 명확하면 바로 보고서를 보여준다.
애매하다고 해서 무조건 질문하지 않는다.

---

## 0. 범위

입력: `"작년 서울 노트북 얼마나 샀어"` → 시스템이 해석하는 것: 기간, 지역/기관, 품목,
지표, 필요한 차원, 채널 등 보고서 선택에 필요한 조건.

출력: 조건에 맞는 보고서 링크 + 왜 이 보고서인지 근거 1줄.
숫자 자체를 계산하거나 반환하는 것은 이 루프의 범위가 아니다.

> **131개 중 맞는 보고서를 가능한 적은 대화로 찾는다.**

---

## 1. 상태 (최소)

```text
state = {
  slots: {...},       // 현재까지 확정된 사용자 조건
  asked: [...],       // 이미 물어본 항목
  turns: n            // clarify 횟수
}
```

후보 목록이나 판단 로그는 필요할 때 매번 계산한다.
서버 세션은 두지 않고 `query_state`를 클라이언트가 전달한다 (현행 유지).

---

## 2. 매 턴 처리

사용자 발화를 받으면 먼저 기존 조건과 병합한다.
사용자가 기존 조건을 명시적으로 수정하면 새 값으로 교체한다. (예: "서울 아니고 경기야" → region: 서울 → 경기)
명시적으로 수정하지 않은 조건은 임의로 버리지 않는다.

```text
1. 명시 조건으로 맞지 않는 보고서를 제거한다.
2. 후보가 1개면 바로 답한다.
3. 1위가 충분히 명확하면 바로 답한다.
4. 질문 하나로 후보를 크게 줄일 수 있으면 아직 묻지 않은 항목 하나만 질문한다.
5. 그 외에는 상위 2~3개를 보여주고 끝낸다.
```

위에서 조건이 만족되면 아래 단계는 실행하지 않는다.

---

## 3. 질문 여부 (절반 규칙)

현재 후보가 `N개`이고 어떤 질문을 했을 때, 사용자가 어떤 답을 하더라도 남는 후보가
최대 `M개`라면, `M <= N / 2` 일 때 질문할 가치가 있다고 본다.
여러 항목이 조건을 만족하면 후보를 가장 많이 줄이는 항목 하나만 묻는다. 한 턴에 질문은 항상 하나.

## 4. 질문 횟수 (최대 1회)

초기 버전 clarification 최대 **1회** (`turns >= 1` → 추가 질문 없음).
한 번 물어도 좁혀지지 않으면 상위 후보를 보여준다.
두 번째 질문이 정확도를 의미 있게 높이는 것이 확인될 때만 최대 2회로 늘린다.

## 5. 그냥 보여줘

clarification UI에는 항상 `그냥 보여줘` 선택지를 둔다. 선택 시 즉시 질문 중단하고 현재 상위 후보를 보여준다.

## 6. 답변 방식

- 충분히 명확하면 보고서 1개 (+ 이동/직접열기 + 근거 1줄).
- 모호성 잔존 시 억지로 1개를 고르지 않고 상위 2~3개 + 남은 차이 1줄 설명.

## 7. 하드 가드레일 (코드 강제)

- 명시 조건 불일치 제거 / 후보 밖 보고서 생성 금지 / 사용자 조건 보존 / 실패 시 종료(상위 2~3개 반환).

## 8. LLM 역할 (최소)

- 자연어 → slot update 변환만. 답할지/물을지/종료할지는 코드가 결정.
- 필요 시 clarification 질문 문장 다듬기에만 사용 가능.

## 9. 측정

기존 지표 유지 (recall@5, top1, family 혼동, clarify율, avg_turns, fallback율) +
`wrong_link_rate` (틀린 보고서 제시율) + `clarify_success_rate` (질문 후 순위 개선율).
`sessions.jsonl`로 전후 비교. 개선 없으면 clarification 끌 수 있게 feature flag 유지.

## 10. 구현 순서

판단 로직만 먼저 바꾼다 (검색 구조 그대로): filter → 1개? → top1 명확? → 절반 규칙 질문? → 상위 2~3개.
그 뒤 sessions 평가. 실제 실패 반복 발견될 때만 규칙 추가. 미리 복잡한 예외 금지.

## 11. 한 줄 요약

> **하나로 좁혀지면 바로 보여주고, 한 번 물어서 크게 좁혀질 때만 묻고, 아니면 몇 개 보여주고 끝낸다.**
> 자율성은 많은 판단을 하는 데 있지 않다. 필요 없는 판단을 하지 않는 데 있다.
